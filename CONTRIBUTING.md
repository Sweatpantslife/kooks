# Contributing to Kooks

Start with the [README](README.md), the [developer handoff](docs/handoff.md) for what is finished and what is not, and [current decisions](docs/decisions.md) for choices that are already settled.

## Set up

Use Node.js 22.13 or newer and npm, and install from the committed lockfile:

```sh
npm ci
npx playwright install chromium   # once, for the browser tests
```

## Checks

Run these before opening a pull request. CI runs the same ones on Node 22 and 24 for every pull request, with the unit tests under `npm run test:coverage`, which also writes `coverage/lcov.info` and puts a per-directory coverage table in the job summary.

```sh
npm run format:check   # Prettier; `npm run format` rewrites files
npm run lint           # ESLint's recommended rules (eslint.config.js)
npm test               # Node unit and integration tests
npm run test:e2e       # Playwright: the mobile, web and web-auth projects
```

`KOOKS_TEST_OCR=1 npm test` also runs the real OCR test, which needs Tesseract (or the command-line tools on macOS). `PLAYWRIGHT_CHANNEL=chrome` runs the browser tests in an installed Chrome, and `PLAYWRIGHT_EXECUTABLE_PATH` points them at a specific Chromium binary. The handoff's [verification section](docs/handoff.md#meaningful-verification) says what each suite covers.

## Making a change

- Keep a pull request to one coherent change, with tests, and say in its description what changed and how you checked it.
- Keep the documentation in step with the behaviour: the README, the guides in `docs/`, and `docs/decisions.md` for a settled choice. `docs/ia-ux.md` is the authority for navigation and interface structure.
- Add an entry to [CHANGELOG.md](CHANGELOG.md) under **Unreleased**: what changed, the checks you ran with their counts, and what was not exercised (native builds, real devices, real mail or OCR).
- Use synthetic data in tests, fixtures, screenshots and issues. Never commit a personal cookbook, backups, photos, `.env` files, logs or signing material. `.gitignore` covers the usual names, but it cannot protect a file that is already tracked.

## Code conventions

- Everything is an ES module. Vite builds the browser app in `client/` (Preact components in JSX, `npm run build:client`) and the mobile app in `app/`; the server serves `client/dist`.
- `shared/` holds dependency-free modules that the apps and the server use. Logic both clients need belongs there rather than in a second copy.
- Validation lives in `mcp/schemas.js`, `mcp/feature-schemas.js` and `mcp/library-schemas.js`, and the browser server and the MCP tools share it. Keep optimistic versions, request IDs, snapshots and shopping preview tokens working for every client.
- The browser app imports each icon from `lucide` by name. The mobile app's `shared/icons.js` is generated by `npm run icons` (add the icon's name to `scripts/icons.mjs`), and the native icons and launch screens by `npm run native:assets`. Regenerate them rather than editing them by hand.

## Dependencies

Kooks keeps few dependencies on purpose: passkeys and mail use Node's own crypto and sockets. The runtime dependencies are pinned to exact versions, development tools use caret ranges, and `package-lock.json` is committed. Prefer Node's standard library over a new package, add a new dependency in its own pull request, and keep `npm audit` clean.

## Security

Report vulnerabilities privately as [SECURITY.md](SECURITY.md) describes, not in an issue.
